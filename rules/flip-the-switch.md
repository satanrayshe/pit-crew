# Flip the Switch: rules and judging, in short

A summary of the hackathon this crew was built for, written to paste into the
template's **Mission** field (the scout turns it into the checklist). Checked
against the sources below on November 5, 2026. Where they disagree, both are
given. The official pages win over this file.

Sources:

- WeMakeDevs event page: https://www.wemakedevs.org/hackathons/switch
- Official rules: https://www.wemakedevs.org/hackathons/switch/rules
- Submission form: https://www.wemakedevs.org/hackathons/switch/submit
- DevTools Academy page: https://www.devtoolsacademy.com/hackathons/flip-the-switch
- Switch repository: https://github.com/sandbox-quantum/switch

## When and who

- November 4, 12:01 AM IST to November 7, 11:59 PM IST. Submissions close at
  the end of the window, with no late window.
- Solo or teams of up to 4. Free to enter. 18 or older (or the age of
  majority where you live).
- One identity per person. Register and submit by hand: the official rules
  forbid bots, scripts and automated agents for registration or submission.

## What to build

- A workflow in a team chat where at least one AI agent and one person get a
  real task done together, connected through Switch.
- Switch has to be central to the project, and the README should show how you
  used it: which agents you connected, how the channel is set up, and how to
  run it.
- Existing agents, libraries and templates are fine. The Switch setup and the
  workflow your agents run have to be built during the hackathon.
- AI coding tools are allowed. You should understand what you submit and be
  able to explain how it works.

## What to submit

Through the form, by hand. Required fields:

- Project title, description, and the tracks you enter (more than one is
  allowed).
- A public GitHub repository with a README that explains how to set it up.
- A demo video under 3 minutes on YouTube or Loom, public or unlisted. For
  tracks 1 and 2 it should show the agent working in a real chat with your
  teammates; for track 3, your most important contribution.
- How you used Switch (which agents, which platforms, what real work it does),
  and what you liked and would improve.

Optional fields: pull request links (required for Best Core Contribution), a
blog post link, your Wispr usage card, your #HowISwitch post.

## Track 03 rules (pull requests to Switch)

- Only issues labelled `hackathon` count. Link the issue in the pull request
  description with `Closes #number`.
- Up to 5 pull requests open at a time. Low-effort pull requests (typo fixes,
  formatting, unreviewed AI output) are not judged. Spam gets you removed.
- The event page says a pull request for an issue not assigned to you is not
  judged; maintainers said on November 3 and 4 that assignment is not needed
  and several people may work on one issue. Only one pull request is selected
  per issue.
- Sign the contributor agreement (CLA) on your first pull request, and run
  the checks in CONTRIBUTING.md before opening one.
- The maintainers judge correct solutions on clean, readable code.

## How projects are judged

| Criterion | Weight | The question |
|---|---|---|
| Use of Switch | 30% | Is Switch central to the project, and would it stop working without it? |
| Technical execution | 25% | Does it run, and could someone clone the repo and reproduce it? |
| Creativity and impact | 25% | Is it a fresh idea that solves a problem a real team has? |
| Presentation and documentation | 20% | Do the demo video and README make it clear what you built and how Switch is used? |

WeMakeDevs reviews every submission and builds a shortlist; Switch, DevTools
Academy and WeMakeDevs judge the finalists. Best Blog is judged on clarity,
accuracy, and how much it helps a first-time Switch user.
